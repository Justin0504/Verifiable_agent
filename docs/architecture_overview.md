# Verifiable Agent：自演化幻觉检测框架

## 一、项目概述

我们搭了一个能"自我进化"的 LLM 幻觉检测系统。核心卖点：**不微调参数，纯靠 prompt 优化 + 规则蒸馏，让检测准确率随训练轮次持续上升。**

系统在每个 epoch t 维护一个完整的状态：

| 符号 | 名称 | 作用 |
|------|------|------|
| P_t | Proposer 策略 | 控制生成什么样的训练数据 |
| V_t | Verifier Prompt | 当前最优的验证 system prompt |
| R_t | ReasoningBank | 结构化推理规则库 |
| M_t | 弱点画像 | 记录 Verifier 当前的错误模式 |
| D_t | 训练数据集 | 经过筛选的高质量验证数据 |

每轮 epoch 结束后，这五个组件全部更新，进入下一轮循环。

## 二、三阶段流水线

### Stage 1：Proposer（出题者）

Proposer 负责生成训练数据，覆盖六类验证场景：

| 类别 | 标签 | 说明 | 例子 |
|------|------|------|------|
| 改写识别 | S | 声明用不同的话说了同一件事 | 证据说"拿破仑身高5尺7寸"，声明说"拿破仑身高中等" |
| 微妙矛盾 | C | 改了一个关键细节（数字、名字、日期） | 证据说"2019年发现"，声明说"2018年发现" |
| 话题重叠 | N | 同一领域但说的不是同一件事 | 证据讲的是火星大气，声明讲的是火星地质 |
| 部分匹配 | S | 声明说的没错但不够精确 | 证据说"增长23.5%"，声明说"增长超过20%" |
| 否定翻转 | C | 直接反了 | 证据说"没有证据表明X"，声明说"研究证实了X" |
| 无关内容 | N | 完全不同的话题 | 证据讲量子物理，声明讲法国大革命 |

**关键设计：弱点感知生成。** Proposer 不是随机出题，而是根据 Verifier 上一轮的错误模式来定向出题。比如发现 Verifier 老是把 S 误判成 C，下一轮就多出这类容易混淆的改写识别题。

### Stage 2：Responder（被测模型）

- 在 benchmark 评估中：直接用数据集提供的答案（如 TruthfulQA 的正确/错误回答）
- 在实际部署中：接入任意目标 LLM，收集它的真实回复

### Stage 3：Verifier（验证者）

Verifier 是系统核心，分四步完成验证：

1. **原子声明分解**：把模型回复拆成独立的事实声明
   - 输入："拿破仑是法国皇帝，他在1815年滑铁卢战败"
   - 输出：["拿破仑是法国皇帝", "拿破仑在1815年滑铁卢战败"]

2. **证据检索**：为每个声明从知识库中找到相关证据

3. **声明级验证**：逐个判断每个声明的标签
   - **S（Supported）**：证据支持该声明
   - **C（Contradicted）**：证据与该声明矛盾
   - **N（Not enough info）**：证据不足以判断

4. **置信度加权聚合**：汇总所有声明的判断，得到回复级别的幻觉评分
   - 每个声明有一个置信度分数（0-1）
   - S 对应幻觉分 0，N 对应 0.5，C 对应 1
   - 最终分数 = 所有声明评分的加权平均

## 三、自演化循环（核心创新）

每轮 epoch 的完整流程：

### Step 1：基线校准（仅第 0 轮）

用 20% 的真实 benchmark 数据作为校准集，跑一遍 epoch 0 的 Verifier，记录：

- 基线准确率（比如 71.2%）
- 具体错误分布（哪些类型判错了、错了多少次）
- 初始弱点画像

### Step 2：生成训练数据

| 数据来源 | 数量 | 说明 |
|----------|------|------|
| 验证技能数据 | 每轮约 24 条 | 覆盖六类验证场景 |
| 对抗性数据 | 每轮约 12 条 | 专门针对当前弱点 |
| 经金标签验证后 | 约保留 80-90% | 丢弃标签不正确的 |
| 经 Soft R-Zero 后 | 保留最难的 60% | 丢弃太简单的 |

### Step 3：金标签验证（Self-Challenging）

每个合成样本的标签都让 LLM 独立检查一遍：

- 给 LLM 看声明、证据、标签，问"这个标签对不对？"
- 标签不对的直接丢掉
- 宁可数据少也要保证质量
- 参考 Self-Challenging（arXiv 2506.01716）的思路：生成的数据可能 95% 都有问题，必须过滤

### Step 4：Soft R-Zero 数据筛选

对每个样本让 Verifier 判断 3 次，看它有多"纠结"：

| Verifier 表现 | 不确定性 | 处理方式 |
|---------------|----------|----------|
| 3 次全对 | 低（太简单） | 丢弃 |
| 2 对 1 错 | 中等 | 保留 |
| 1 对 2 错 | 高（边界案例） | 优先保留 |
| 3 次全错 | 低（可能标签有问题） | 丢弃 |

按不确定性从高到低排序，保留前 60%。这比原始 R-Zero 的硬过滤好——硬过滤经常把数据全删光。

### Step 5：Prompt 精炼 + 验证门控

这是自演化最关键的一步：

1. 分析训练集上的错误模式（哪些类型错最多、具体案例是什么）
2. 让 LLM 根据错误分析重写 Verifier 的 system prompt
3. **验证门控**：新 prompt 必须在真实校准集上准确率 **严格高于** 当前最优才接受
   - 接受 → 更新最优 prompt，更新弱点画像
   - 拒绝 → 回滚到旧 prompt，不做改动

为什么必须用真实数据验证：如果只在合成数据上验证，prompt 可能过拟合合成分布，在真实数据上反而变差。

### Step 6：ReasoningBank 规则蒸馏

从每轮的预测结果中提取结构化推理规则：

| 来源 | 提取数量 | 内容 |
|------|----------|------|
| 失败案例 | 最多 3 条 | "别这么做"的反面教训 |
| 成功案例 | 最多 2 条 | "这么做有效"的正面经验 |

规则存入 ReasoningBank，下次遇到类似声明时取 top-1 最相关的规则注入到 prompt 里。只取 1 条是为了避免 prompt 膨胀。

### Step 7：弱点画像更新

根据校准集上的最新错误分布，生成下一轮 Proposer 的指导：

- "S→C 混淆仍然严重，多出改写识别的题"
- "C→N 改善了，可以减少这类题"
- "N→S 是新出现的问题，需要关注"

---

## 四、测试阶段

训练结束后，用最优 prompt 在 **独立的测试集（80%）** 上评估：

- 每个样本跑 3 次独立验证（R-Zero 的测试时集成）
- 取多数投票作为最终预测
- 与 6 个 baseline 在相同测试集上公平对比

## 五、参考论文及借鉴点

| 论文 | 来源 | 我们借鉴了什么 |
|------|------|----------------|
| R-Zero | ICLR 2026 (arXiv 2508.05004) | 不确定性驱动的数据选择、多次采样一致性过滤、测试时多数投票 |
| Self-Challenging | arXiv 2506.01716 | 生成数据的可执行验证（金标签检查），激进过滤保证质量 |
| ReasoningBank | arXiv 2509.25140 | 从成功+失败轨迹蒸馏规则，top-1 检索注入，避免 prompt 膨胀 |
| A-MEM | arXiv 2502.12110 | 结构化记忆设计思路，弱点画像的演化存储 |
