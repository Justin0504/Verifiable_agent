Verifiable Agent

自演化幻觉检测框架 — 架构与实现细节

一、我们在解决什么问题

大语言模型（LLM）会生成看起来很合理但实际上不正确的内容，也就是「幻觉」。现有的检测方法（FActScore、SAFE、CoVe 等）都是静态的——用固定的 prompt 跑一遍就完了，不会从自己的错误中学习。

我们的方案不一样：搭一个能自我进化的检测系统。不微调模型参数，纯靠优化 prompt 和积累推理规则，让检测准确率随训练轮次持续上升。核心思路是「出题→验证→找错→改进→再出题」的闭环迭代。

二、系统整体架构

系统由三个阶段组成一个流水线（Proposer → Responder → Verifier），加上一个自演化循环把它们串成闭环。每个 epoch（训练轮次）结束后，系统的五个核心组件全部更新：

组件名称作用怎么更新
P_tProposer 策略控制生成什么样的训练数据根据弱点画像调整出题方向
V_tVerifier Prompt验证时用的 system prompt通过 prompt 精炼 + 验证门控更新
R_tReasoningBank结构化推理规则库从成功/失败轨迹中蒸馏新规则
M_t弱点画像Verifier 当前的错误模式每轮根据校准集结果更新
D_t训练数据集经过筛选的高质量验证数据每轮重新生成 + 过滤

三、三阶段流水线详解

Stage 1：Proposer（出题者）

Proposer 负责生成高质量的 claim-evidence 训练对。这里有两个关键设计：

设计一：验证技能导向。我们不是让 LLM 随便编数据，而是要求它按照六类具体的验证场景来出题。每一类测试的是不同的推理技能，不是知识储备。

验证场景标签测什么能力具体例子
改写识别S能否看出不同措辞说的是同一件事证据：「拿破仑身高5尺7寸」
声明：「拿破仑身高在当时算中等水平」
微妙矛盾C能否抓住一个关键细节的变化证据：「该研究于2019年发表」
声明：「该研究于2018年发表」
话题重叠N能否区分同领域但不同事实证据：讲的是火星大气成分
声明：讲的是火星地表温度
部分匹配S能否接受精度较低但正确的表述证据：「GDP增长了23.5%」
声明：「GDP增长超过20%」
否定翻转C能否识别语义取反证据：「没有证据表明X有效」
声明：「研究证实X有效」
无关内容N能否判断完全不相关的话题证据：讲量子物理
声明：讲法国大革命

设计二：弱点感知生成。Proposer 不是均匀地出题，而是根据 Verifier 上一轮暴露的弱点来调整。比如上一轮发现 S→C 误判最多（12次），下一轮就会重点出「改写识别」和「部分匹配」这类容易被误判为矛盾的题目。同时还会专门生成对抗性样本——刻意让 claim 和 evidence 看起来很像但标签不同，逼 Verifier 学会精细区分。

Stage 2：Responder（被测模型）

Responder 是被检测的目标 LLM。在两种场景下有不同的角色：

  • Benchmark 评估：直接使用数据集提供的回答。比如 TruthfulQA 里每个问题已经有正确答案和常见错误答案，我们直接拿来验证。
  • 实际部署：接入任意目标 LLM（GPT-4o、Claude、Llama-3 等），向它发送 Proposer 生成的问题，收集真实回复。

Stage 3：Verifier（验证者）

Verifier 是整个系统的核心，完成从原始回复到幻觉评分的全过程。分四个子步骤：

3.1 原子声明分解

用 LLM 把模型回复拆解成独立的、可单独验证的事实声明。每个声明只包含一个可验证的事实断言。

示例输入：「拿破仑是法国皇帝，他在1815年的滑铁卢战役中败给了英国联军。」

示例输出：[「拿破仑是法国皇帝」, 「拿破仑在1815年的滑铁卢战役中战败」, 「拿破仑的对手是英国联军」]

3.2 证据检索

为每个原子声明从知识库中检索最相关的证据段落。在 benchmark 评估中，证据直接由数据集提供（比如 TruthfulQA 的 best_answer + correct_answers）。在通用场景中可以对接 Wikipedia、搜索引擎等外部知识源。

3.3 声明级验证（S/C/N 分类）

对每个声明-证据对，LLM 输出一个三分类判断和置信度：

标签含义判断标准幻觉分
S (Supported)证据支持证据中能找到直接或间接支持该声明的信息0
C (Contradicted)证据矛盾证据中的信息与该声明存在事实冲突1
N (Not enough info)信息不足证据没有涉及该声明的内容，无法判断0.5

这一步是自演化重点优化的对象。Verifier 的 system prompt（V_t）决定了分类质量，而这个 prompt 会在每轮 epoch 中被精炼。如果 ReasoningBank 中有和当前声明相关的推理规则，也会注入到 prompt 中辅助判断。

3.4 置信度加权聚合

一个回复可能拆出 3-6 个声明，需要汇总成一个回复级别的判断。我们的聚合规则：

  • 如果有任一声明被高置信度（≥ 0.8）判为 C，整个回复判为 C（矛盾优先）
  • 否则，按每个声明的置信度做加权投票，票数最高的标签胜出
  • 平票时优先级：C > N > S（保守策略，倾向于报告潜在问题）
为什么不用旧的严格规则（「只要有一个 C 就判 C，全是 S 才判 S」）？因为 TruthfulQA 的 S 类样本有 3-6 个 claims，只要其中一个被误判为 N，整个样本就会从 S 变成 N。这是之前 Verifier 只有 59% 而 FActScore 有 71% 的主要原因。

四、自演化循环（核心创新）

自演化是区别于所有 baseline 方法的核心。每轮 epoch 执行以下完整流程，形成「出错→学习→变强」的闭环：

Step 0：基线校准（仅首轮）

从 benchmark 数据中取出 20% 作为校准集（calibration set），剩余 80% 作为最终测试集。用 epoch 0 的 Verifier（没有任何演化）跑一遍校准集，记录：

  • 基线准确率（我们的实验中是 71.2%）
  • 错误分布：哪些标签之间最容易搞混（比如 S→C 有 12 次，C→N 有 8 次）
  • 初始弱点画像：告诉 Proposer 第一轮该重点出什么题
为什么用真实数据做校准？之前的版本（v8）只在合成数据上评估，结果合成数据太简单，Verifier 全答对，学不到东西。用真实 benchmark 数据才能发现真正的弱点。

Step 1：生成训练数据

每轮 epoch 生成两类数据：

数据类型每轮数量生成方式目的
验证技能数据约 24 条LLM 按六类场景生成覆盖各种验证能力
对抗性数据约 12 条LLM 根据弱点画像定向生成专攻 Verifier 的薄弱环节

Step 2：金标签验证（Self-Challenging）

LLM 生成的数据质量参差不齐，标签可能是错的。我们让另一个 LLM 调用独立检查每个样本的标签是否正确：

  • 给 LLM 看 claim、evidence、标签，问「这个标签对不对？为什么？」
  • 如果判定标签不对，直接丢弃这个样本
  • 通常保留 80-90% 的样本（比 Self-Challenging 论文中 5% 的留存率宽松，因为我们的生成质量更高）
核心思想：宁可训练数据少，也要保证每一条的标签是对的。用错误标签训练只会让 Verifier 越来越差。

Step 3：Soft R-Zero 数据筛选

不是所有数据都有同等的训练价值。Verifier 已经能轻松答对的题没有学习意义，真正有价值的是「边界案例」——Verifier 半对半错、很纠结的那些。

具体做法：对每个样本让 Verifier 独立判断 3 次，统计正确率：

3 次判断结果正确率不确定性处理
全对 (3/3)100%低 — 太简单了排在后面，可能被丢弃
对 2 错 1 (2/3)67%中等 — 有点难保留
对 1 错 2 (1/3)33%高 — 很纠结优先保留
全错 (0/3)0%低 — 可能标签有问题排在后面，可能被丢弃

按不确定性从高到低排序，保留前 60%。

为什么叫「Soft」R-Zero？原始 R-Zero 论文用硬阈值过滤（正确率在 25%-75% 之间才保留），但我们发现简单的合成数据上 Verifier 要么全对要么全错，硬过滤会把数据全删光（v8 就是这样挂的，52 条全删到 0）。所以我们改成排序 + 取 top-60%，保证每轮至少有足够的训练数据。

Step 4：训练 + Prompt 精炼 + 验证门控

这是自演化最核心的一步，分三个阶段：

阶段 A：在合成数据上跑 Verifier。记录每个样本的预测结果，分析错误分布（哪些标签对混淆最严重、具体错在哪里）。

阶段 B：LLM 生成改进后的 prompt。把当前 prompt、错误分析、具体错误案例发给 LLM，让它写一个更好的 system prompt。要求新 prompt 控制在 250 词以内，明确 S/C/N 的判断标准，针对性修复错误模式。

阶段 C：在真实校准集上验证。这是关键——新 prompt 不是生成出来就用，必须在真实 benchmark 校准集上的准确率严格高于当前最优 prompt 才会被接受。如果没有提升甚至变差了，直接回滚，当这轮 prompt 改动没发生过。

情况操作原因
新 prompt 校准准确率 > 旧✅ 接受，更新最优 prompt确实变强了
新 prompt 校准准确率 = 旧❌ 拒绝，回滚没有提升不算进步
新 prompt 校准准确率 < 旧❌ 拒绝，回滚变差了，不能用

Step 5：ReasoningBank 规则蒸馏

从每轮的预测结果中提取可复用的推理规则，存入 ReasoningBank：

规则来源每轮提取内容作用
失败案例最多 3 条「别这么做」的反面教训比如「当 claim 和 evidence 讲的是同一实体的不同属性时，应该判 N 而不是 C」
成功案例最多 2 条「这么做有效」的正面经验比如「当 claim 用不同数字表述但量级一致时，应该判 S」

规则的使用方式：下次 Verifier 遇到新的声明时，从 ReasoningBank 中检索最相关的 1 条规则，注入到当前的 prompt 中辅助判断。只取 top-1 是为了避免 prompt 膨胀——塞太多规则反而会干扰 LLM 的判断。

Step 6：弱点画像更新 → 驱动下一轮

根据校准集上的最新错误分布，更新 Proposer 的出题指导：

  • S→C 混淆仍然最严重（8 次）→ 继续多出改写识别和部分匹配的题
  • C→N 从 8 次降到了 3 次 → 这类题可以减少，已经学会了
  • N→S 是新出现的问题（4 次）→ 下一轮重点出话题重叠的题

这样形成了一个完整的闭环：弱点画像指导 Proposer 出题 → Verifier 在难题上训练 → prompt 精炼修复弱点 → 新的弱点画像 → 下一轮……

五、测试阶段

15 轮 epoch 训练结束后，用最优 prompt 在独立测试集（80%）上做最终评估：

  • 每个样本跑 3 次独立验证，取多数投票作为最终预测（R-Zero 的测试时集成思路）
  • 与 6 个 baseline 方法在完全相同的测试集上对比，保证公平性
  • 报告 Accuracy、Macro F1、每类标签的混淆矩阵
Baseline 方法类型核心思路
Direct Prompting零样本直接问 LLM 这个回答对不对
FActScore分解+验证拆成原子事实逐个验证（我们 Stage 3 的基础版）
SAFE多步搜索Search-Augmented Factual Evaluation，用搜索引擎辅助
CoVe自我一致性Chain-of-Verification，让模型自己检查自己
SelfCheckGPT采样对比多次采样同一问题，比较回答一致性
Retrieve+NLI检索+推理检索相关文档 + NLI 模型判断蕴含/矛盾
