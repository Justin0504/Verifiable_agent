我们在做什么

简单说，我们搭了一个能"自我进化"的幻觉检测系统。它不需要微调模型参数，纯靠优化 prompt 和积累推理规则，就能让检测准确率越来越高。


整体流程

系统分三个阶段跑，形成一个闭环：

1、Proposer（出题者）：自动生成用来训练 Verifier 的验证数据。不是随便出题，而是根据 Verifier 当前的弱点来出——比如发现 Verifier 经常把"支持"误判成"矛盾"，下一轮就专门出这类容易搞混的题。这个思路参考了 R-Zero（ICLR 2026）的不确定性驱动数据选择。

2、Responder（被测模型）：就是我们要检测的目标 LLM。在 benchmark 实验里直接用数据集提供的回答，在实际部署中可以接任何模型。

3、Verifier（验证者）：核心模块，分三步走：
- 把回复拆成一个个原子化的事实声明
- 从知识库里检索每个声明对应的证据
- 逐个判断每个声明是"被支持(S)"、"被矛盾(C)"还是"信息不足(N)"
- 最后通过置信度加权投票汇总，给出整体的幻觉评分


自演化怎么跑的

每轮 epoch 做这几件事：

第一步，找出哪里错了。把 Verifier 的预测和真实标签对比，分类出三种错误：假阳性（说人家矛盾其实没有）、假阴性（说支持其实是矛盾）、边界案例（S 和 N 分不清）。

第二步，改 prompt。根据错误分析让 LLM 重写 Verifier 的 system prompt。但不是改了就用——必须在真实 benchmark 的校准集上跑一遍，准确率严格高于之前才接受。这个验证门控很重要，防止 prompt 越改越差。

第三步，蒸馏推理规则。参考 ReasoningBank 那篇论文，从失败案例里提取"别这么做"的教训，从成功案例里提取"这么做有效"的经验，存成结构化规则。下次遇到类似的声明，取最相关的 1 条规则注入到 prompt 里辅助判断。

第四步，筛选训练数据。用 Soft R-Zero 方法：对每个合成样本让 Verifier 判断多次，看它有多"纠结"。越纠结的样本越有训练价值，保留最难的 60%。太简单的题（Verifier 全答对）直接扔掉，因为学不到东西。

第五步，更新弱点画像。根据这轮的错误分布，告诉 Proposer 下一轮该重点出什么题。

这样每轮循环下来，Proposer 出的题越来越有针对性，Verifier 的 prompt 越来越精准，规则库越来越丰富。


几个关键的设计选择

金标签验证：每个合成数据的标签都让 LLM 再检查一遍，标签不对的直接丢掉。参考的是 Self-Challenging 那篇论文的思路，宁可数据少也要保证质量。

多数投票聚合：一个回复拆出来可能有 5 个声明，以前的做法是只要有一个判成 C 整个就是 C，太严格了。我们改成置信度加权投票，但如果有个声明被高置信度（大于 0.8）判成 C，还是会优先采纳。

测试时 3 次投票：最终测试的时候每个样本跑 3 遍取多数，提升稳定性。


目前的效果

在 TruthfulQA 上，Verifier 的校准集准确率从初始的 71.2% 经过第一轮演化就到了 82.5%，提升了 11 个点。实验还在跑（一共 15 轮 epoch），跑完会和 6 个 baseline 方法做公平对比。
